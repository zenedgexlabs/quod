# E8: The agent loop, end to end through MCP

**Question:** when a coding agent follows Quod's MCP answers, calling
`tests_for` and running the command it returns instead of the whole
suite, does it still see every failure its change causes? And how much
does it run?

**Method** (`conformance/agent_loop.py`). A map is recorded at a real
commit G. Then, for each of the next ten real first-parent commits C:

1. The repository is left the way an agent leaves it: HEAD at C's parent
   and C's change uncommitted in the working tree. Odd steps add a
   mutant (as in E1) on top, standing in for an agent's bug.
2. `tests_for` is called through `quod mcp` over stdio, as an agent calls
   it. Environment mode comes from detection (`QUOD_PYTHON`, `QUOD_JS`),
   not flags.
3. An untimed warm-up run fills the runner's caches.
4. The returned `run` command is executed exactly as returned.
5. The same command runs with an empty skip file: the full suite, with the
   same costs (probe loaded, no recording). That run is the ground truth.

Scoring:

- **Escape:** a test fails in the full run and fails alone three times,
  but the returned command didn't run it.
- **Missed collection error:** the full suite couldn't be collected (a
  broken import) and the returned command still exited 0. This also
  counts as an escape.

The gate is 0 escapes.

The map stays at G for all ten steps, so by the last step it is nine
commits behind HEAD. Selection compares the working tree with the map's
commit, so later steps also re-run the tests for earlier steps' changes.
CI publishes a map for every green commit, so the map an agent pulls is
usually 0 to 2 commits behind. These fractions are therefore a
pessimistic bound.

| itsdangerous | pytest | 10 | ~297 | 1.2 s | 250 | 250 | **0** | 79% | 96% | 95% |
| attrs | pytest | 10 | ~1,285 | 8.4 s | 13, plus 1 collection error | 13, plus the error (exit 2) | **0** | 78% | 100% | 82% |
| more-itertools | pytest | 8 | ~771 | 14.5 s | 18 | 18 | **0** | 82% | 43% | 49% |
| ufo | Vitest | 10 | ~483 | 7.5 s | 41 | 41 | **0** | 9% | 34% | 35% |
| remeda | Vitest | 10 | ~2,572 | 8.6 s | 134 | 134 | **0** | 72% | 97% | 87% |
| luxon | Jest | 10 | ~1,195 | 10.4 s | 548 | 548 | **0** | 100% | 102% | 219% |

**0 escapes in 58 steps, 1,004 of 1,004 failing tests caught.** "Time" is
the returned command's wall time over the full run's. The total is
skewed by single stalls (luxon step 10 took 139 s against 10 s, with
identical commands), so the median step is the better guide.

In more-itertools, two mutant steps were dropped because the suite hangs
under them. No test that failed in the full run passed in the returned
command's run, so there were no order-dependent victims.

**Where it saves time, and where it doesn't.**

- **Slow tests, or many test files.** more-itertools skips its slow tests
  (82% of the tests in 43% of the time). ufo runs 9% of the tests, and
  test files whose every test is skipped aren't even loaded, so a step
  costs about a third of the full run.
- **Fast suites.** itsdangerous (1.2 s) and attrs (8 s) are dominated by
  start-up and collection: running 78% of the tests costs about the same
  as running all of them. On suites this fast, what Quod adds is the
  certificate for each skip, not speed.
- **Module-level changes reach everything.** In attrs, remeda and luxon,
  most steps change code at module level in a module nearly every test
  imports. Since ADR 019 that re-runs every test that imported the
  module or ran any of its functions, which is what soundness requires.
  remeda also runs with `isolate: false`, so each test file is credited
  with every module its worker loaded. On remeda the first three steps
  ran 7 to 387 of 2,558 tests (35% to 67% of the time); from step 4 on,
  a change in the map's window reaches nearly all of them, and steps 9
  and 10 change `vitest.config.ts` (R002).
- **luxon ran everything.** In this window `src/impl/util.js` only gains a
  new exported function, and `util.js` is imported everywhere. ADR 020
  (implemented since for JavaScript and TypeScript) no longer counts that
  as a module change. luxon still runs everything here, correctly:
  `duration.js` and `regexParser.js` change module-level code (new
  imports) in the same window.

## What changed since the first version of this page

The first results (2026-11-26) were wrong in Quod's favour in two ways,
and E8 found two soundness bugs. All numbers above come from one run of
the corrected harness on the fixed engine and probes.

- **Ground truth.** The full run used to be the recording run, which pays
  for tracing every test. It now runs the same command as the agent with
  an empty skip file.
- **Cached imports (ADR 019).** A module's body runs once per process. A
  test whose module imported `util` second recorded nothing of `util`'s
  top level, so a changed module constant could skip it: a false green,
  reproduced on a two-file repository. Fixed in the engine (a module-level
  change also runs every caller of the module's functions) and in both
  probes (Python import closures; JS module evaluation under Vitest
  `isolate: false`). This costs precision: on itsdangerous the tests run
  went from 61% to 79%.
- **Plain-name defaults (ADR 011 addendum).** `def f(b=SENTINEL)` was
  treated as a change to `f` only, but an unbound name fails the module's
  import. Only builtin names are now free of side effects.
- **Harness.** The agent's command always ran first and paid for cold
  caches (on luxon, identical commands took 11.1 s vs 8.5 s): an untimed
  warm-up now comes first. A timeout is retried once, because the
  clock also runs while the machine sleeps.
- **Whole test files.** A small selection still paid for collecting every
  test file (ufo: 9% of the tests in 105% of the time). Test files whose
  every recorded test is skipped are no longer collected (pytest, Vitest
  including inline projects, Jest).

Runs were also disturbed by other work on the same machine (a timer-based
remeda test failed under load and was counted as an escape). Every repo
was re-run on an otherwise idle machine.

## What this does not cover

Every step ran in the environment the map was recorded in. When the
agent's environment differs from CI's (another OS, interpreter or package
set), Quod runs every test (rule R018) and says why. That is sound, and it
saves nothing. A real LLM agent working on tasks is E8b.
