# E7: Culprit attribution on real history

**Question:** when main turns red, does `quod culprit` ([ADR 018](../adr/0018-culprit.md))
always include the commit that broke each failing test (soundness), and
how often does it name that commit alone (precision)?

**Method** (`conformance/culprit.py`). Each trial:

1. Records a map at a real commit G, the last green commit.
2. Replays the next five real first-parent commits on a synthetic branch.
   A mutant (as in E1) goes in as its own commit M at a random position,
   and later commits carry it forward.
3. Runs the suite at the mutated end and at the clean end. A test counts
   as broken by M if it fails only with the mutant and fails alone three
   times.
4. Runs `quod culprit` (map at G, G..end) on those tests.

- **Miss:** M is not a suspect, and the answer isn't `unknown`. The gate is
  0 misses.
- **Named alone:** the answer is `culprit` and the commit is M.

## Results (2026-11-25, environment mode)

| repo | trials (with broken tests) | broken tests | misses | unknown | named alone | mean suspects (of 6 commits) |
|---|---|---|---|---|---|---|
| itsdangerous | 5 (2) | 115 | **0** | 0 | 39 (34%) | 1.66 |
| attrs | 6 (3) | 32 | **0** | 0 | **32 (100%)** | 1.00 |
| more-itertools | 4 (4) | 11 | **0** | 0 | 1 (9%) | 2.55 |
| ufo (Vitest) | 6 (3) | 179 | **0** | 0 | **179 (100%)** | 1.00 |

**Path mode, for comparison.** itsdangerous and attrs again had 0 misses,
but 4.79 and 4.19 mean suspects, and nothing was named alone. Their real
commits are mostly CI workflow, `pyproject` and pre-commit edits, which
path-based rules treat as global, so every such commit becomes a suspect.
Environment mode evaluates commits as if the environment were unchanged,
and checks the real environment difference separately. That removed those
suspects without losing soundness.

**Where precision is lost.** In itsdangerous trial 2, 76 of 91 broken tests
also implicated one real commit, which removed deprecated code at module
level in a module those tests import. That is root-scope or module-level
coarseness, the same limit as E1's click and jinja.

In more-itertools, the extra suspects are commits that only add tests to
the failing test's own file. Test class bodies run when the file is
imported, so every test in that file executes them. That coarseness is
deliberate: making it finer would need per-class import attribution.
Before the module-state fixes in ADR 014 (dunder declarations, the test's
own file, read-only constant tables), the mean was 4.08 suspects.

**ufo, step by step.** Each row fixed what the previous run exposed, and
none of the fixes cost soundness (0 misses throughout):

| ufo run | broken tests | unknown | named alone | mean suspects |
|---|---|---|---|---|
| first (5 trials) | 41 | 0 | 0 | 3.00 |
| npm lockfile edits observed through the fingerprint (ADR 012 addendum) | 179 | 2 | 23 | 1.87 |
| Vitest tests with an empty title traced | 179 | 0 | 23 | 1.87 |
| type-checking-only tsconfig options ignored (ADR 013 addendum) | 179 | 0 | **179** | **1.00** |

The extra suspects were, in turn, `chore: update deps` commits (lockfile
edits counted twice, once as a file and once through the installed
packages), and a commit that removed `moduleResolution` from
`tsconfig.json`, which Vite's per-file transpiler never reads. The two
`unknown` answers were a probe naming bug: `test('')` is reported by
Vitest as `suite > `, but the probe recorded `suite`, so those tests were
never traced. The harness also had to learn to re-run tests whose names
contain NUL.
