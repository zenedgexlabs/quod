\* The machine slept during one click step (`6aabf099`), which recorded 7.4

**Soundness.** There were zero dependency escapes and zero change escapes
across 100 history steps and 50 mutants. Every certificate verified,
including the new environment binding. The two victims are the known
order-dependent tests.

**Speed.**

- Environment mode removed every policy-forced full run: 22 in run 3.
- Three repos now pass both 2× speed gates:
  - attrs: 9× less time than the file baseline;
  - itsdangerous: 9×;
  - more-itertools: 4.5×.
- Click and jinja are sound but slower than the baseline. Their remaining
  full runs are all root scope (R017): their conftests import the package,
  and those commits make class-level and module-level changes, such as
  version strings, regenerated tables, added methods and
  `__init_subclass__`. ADR 011 explains why these can't be narrowed soundly
  without attribute-level observation.
- The file baseline is faster there only because it ignores code that runs
  at import time.

**Caveat on versions.** The harness installs dependencies once and replays
every step in the same venv, so a version bump (`project.version`, `uv.lock`)
is no change. That is consistent with its ground truth. In CI, the reinstall
changes the project's distribution hash, which the root scope observes, so a
version bump is a full run.

**Harness changes.**

- Suite runs now time out: 10× the slowest run, at least 15 minutes for
  history steps and 120 seconds for mutants.
- Run 4 (engine `24c450e`, header split only, probe 0.2) was stopped after
  click (0.666) and more-itertools. Its attrs suite hung twice, for reasons
  still unknown, and run 5 supersedes it.


## Run 3: path-based rules

The run finished on 2026-11-22. It used engine `4955a9d` (release build). Probe
0.1 recorded more-itertools, click and attrs; probe 0.2 recorded jinja and
itsdangerous. Probe 0.2 only adds observations, and that engine ignores its
capability, so selection is unchanged.

Each repo replays 20 consecutive commits of real history and 10 single-token
mutants of source code. At every step, the full suite is run to establish
ground truth.

- **Dependency escape:** a test Quod skipped that fails at head when run
  alone. This is a soundness bug. **Gate: zero.**
- **Victim escape:** a skipped test that fails in the full run but passes
  alone. It is order-dependent through state other tests leak (ResourceWarnings,
  global flags). These are a documented assumption, covered by the audit.
- **Change escape:** the change as a whole goes from passing to failing and
  Quod's selection misses it. **Gate: zero.**
- **Time fraction:** the share of full-suite time each method runs.
  - The *baseline* is file-level selection (Ekstazi-style: a test re-runs if a
    file it touched changed). It doesn't treat import-time code as global.
  - The *policy baseline* is the file baseline plus Quod's global policy
    triggers.

**Soundness.** There were zero dependency escapes and zero change escapes
across 100 history steps and 50 mutants. Every certificate verified
independently. The two victims are order-dependent tests, as in run 2. The
file baseline missed one click mutant and one attrs mutant; those are the
same tests counted as victims above.

**Mutants.** Quod runs less than the file baseline in every repo. Function
granularity wins when changes are code.

**History.** Quod beats the baselines only on more-itertools, by 3.3×.

Selective steps are close to free. The cost is path-based global rules:

- **R001:** `.github/workflows/tests.yaml` and `ci.yml` edits, mostly action
  version bumps.
- **R002:** `tox.ini` and the `tool.tox`, `tool.uv`, `tool.gha-update`,
  `project.version` and `project.requires-python` sections.

These rules fire because a file that *could* change the test environment
changed, not because the environment did. On click, the cost is root scope:
its conftest imports the package, and class or module semantics changes are
frequent (see ADR 011).
